# v1.1.1 飞升系统与按钮热修

## 飞升规则

顶部与修炼页的飞升入口始终可点击。未满足时显示距离建议层数、实时预计收益和条件；满足后提供确认按钮；已飞升显示累计效果与下一次预览。面板采用同一收益函数，战斗刷新时立即更新，另外每500ms检查最高层变化。

首次要求最高2000层，不再检查当前塔层或金丹境界。再次飞升取超过上次结算最高层的下一个里程碑：2000、3000、5000、8000。8000层以后下次目标为上次结算层数的1.5倍并向上取整至100层；奖励的最高层修正暂封顶8000，未把平衡矩阵扩展到8000以外。

奖励 = 基础倍率 × 最高层修正 × 次数衰减。基础倍率依次为攻击10%、生命10%、防御9.5%、资源15%、仙缘11%。最高层修正在 `src/ascension_v111.js` 的锚点之间线性插值；次数衰减为 `1 / (1 + 0.25 × 已飞升次数)`。锚点使1250、2035、2450、3000、5000层的示例均可复算。永久加成按百分点相加，不使用连续乘法。

新飞升没有清空列表，不重置塔层、最高层、武将等级/星级/武魂、装备与词条、灵宠、功法、神兵、境界、修为、货币、回廊、临时效果或待领取收益。确认时再次校验条件；存储失败会回滚这次加成与次数。当前战斗保持生命比例，不通过飞升刷新敌人或免费回满血。

攻击、生命、防御直接参与实际属性计算。为避免Boss单击上限抵消攻击成长，2000层以后单击上限也按新飞升攻击加成放大，并受12%基础上限限制；原有破招阶段机制仍保留。旧存档的破限和倍率独立保留。

资源效率作用于铜钱/修为的推塔、离线与按挂机速度计算的秘境/派遣产出；固定兑换奖励不放大。仙缘效率作用于游戏内正向仙缘奖励，保留小数；负向消耗不放大，兑换码仍按原额度发放。成就与事件的仙缘展示同步实际加成。

## 存档迁移

新存档使用 `sgs_idle_v1110`，并保留临时档与备份档；读取顺序优先新档，再回退旧档。损坏档产生恢复日志并继续尝试备份。导出为 `SGST111-` 档码或 `.sgst` 文件；导入继续支持SGST110、SGST1091等31种历史前缀，并验证基本结构。

老版 `1.32^飞升次数 × (1 + 累计仙缘×1%)` 在首次迁移时冻结为兼容权益，新飞升另存 `ascension.bonuses`；迁移本身不会发放新奖励，重复导入不会再次叠加。当前旧档飞升次数用于后续衰减；上次飞升层数缺失时采用历史最高层作为防重复结算边界。

## 按钮与手机

原先原生 disabled 按钮改成可点击的条件说明状态。`buttonActionGuard()` 统一检查直接/委托处理函数与条件，拦截重复异步操作，执行后保证反馈；缺失处理函数、同步异常、异步拒绝均显示“功能加载异常 / 请重新打开页面”。错误存入本地 `errorLog`，最多100条，包含版本、时间、按钮、异常和堆栈。

已对委托路由显式登记，孤立按钮不会被父容器误判成“已响应”。文件导入的异步 change 也经同一防护。移动端使用原生 click，旧Touch API补充touchstart/touchend兼容；超过12px的移动视为滚动，不触发动作。按钮最小44×44px，提示层和战斗特效不拦截指针；飞升弹窗标题/关闭区与底栏不随正文滚走，并支持键盘焦点与Escape关闭。
