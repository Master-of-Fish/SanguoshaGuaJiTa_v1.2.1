目标：证明“挂机 + 修仙无限成长 + 三国武将自动战策”能同时成立。

- 六名机制武将
- 24 将首发数据
- 自动登塔
- 修炼 / 飞升
- 抽卡 / 武魂
- 装备背包自动化
- 离线收益
- 存档导入导出

## v0.2 —— 24 将完整机制

把六个显式规则迁移到 Skill Runtime Hook，然后逐个实现首发 24 将：

- 摸牌/弃牌修改
- 战牌转化
- 响应规则修改
- 判定与改判
- 伤害前后触发
- 装备变化触发
- 低血/卖血
- 连营/资源循环

同时加入武将技能测试场，方便平衡。

## v0.3 —— 修仙 Build 层

优先加入能够直接改变自动牌局的系统，而不是纯菜单：

- 灵根

# 以后你发参考项目时，我们怎么处理

1. **拆解**：先看项目的核心循环、资源、成长、UI 与独特机制。
2. **归因**：判断这个玩法真正解决了什么玩家需求。
3. **对照设计基准**：是否增强挂机、无限成长、突破爽感或武将机制？
4. **改造**：把需要手动刷/复杂操作的设计自动化，把纯数值系统尽量和战策机制发生关系。
5. **模块化接入**：优先新增独立数据和模块，不修改核心存档结构和 BattleSimulator 主流程。
6. **旧档迁移**：新增字段提供默认值，提升 `SAVE_VERSION` 并添加 migration。
7. **回归测试**：验证老玩法、离线、抽卡、背包、存档不被破坏。

因此以后继续发类似项目是非常合适的。项目越接近“挂机爽感、修仙成长、自动卡牌机制、无限装备”中的某一项，参考价值越高。
